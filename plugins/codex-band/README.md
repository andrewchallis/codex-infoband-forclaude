# codex-band

A Claude Code mod that adds one line above the prompt: what Codex is doing right now, or when it last finished, plus a Details button for your Codex Band Requests page on claude.ai.

It reads the Codex plugin's own job records under `~/.claude/plugins/data/<codex plugin>/state/*/state.json` every 15 seconds, so it only shows live jobs on the computer where the Codex plugin runs. On another computer running Claude Code without the Codex plugin, it shows the jobs listed on your requests page instead (read every 30 seconds), and Stop points you to the desktop. Cloud sessions (claude.ai/code tasks) show no band at all: they don't install plugins from a repository's `.claude/settings.json`, and they don't draw what a mod draws. From a cloud task, follow Codex on your requests page, or drive a desktop session with `/remote-control`, where the band is drawn. It stays hidden in a new chat until the session involves Codex: a Codex hand-off (the companion script, a Codex skill or the Codex subagent, shown while it waits for permission), a `/codex:*` command, or a Codex job this session started. `Hide` hides it until Codex comes up again; `/codex-band` shows it, `/codex-band hide` hides it. The first time a session has a Codex job to log, the mod looks for a claude.ai page of yours titled "Codex Band Requests" and, if there is none, creates one (with the usual permission prompt; this needs Claude Code signed in to claude.ai). It remembers the page from then on. Each Codex job a session starts gets a row on that page (doc id = the Codex job id), written by the mod and updated as the job runs and finishes; the mod approves only its own writes to that page's `requests` list. The thread adds the findings and what was done to that row. The page groups requests under the Claude task that raised them (its session title, or the start of its first prompt). Each row shows its Codex chat ID and a `codex resume <id>` command (the page can't open the Codex app), with a note that a chat Claude Code started while the Codex app was open appears in its sidebar after you restart the app (openai/codex#30916). Once Codex comes up in a session, the mod also tells Claude what a Codex plugin worker can't do (no approvals, no thread messaging, read-only unless `--write`), so briefs ask only for work the worker can finish, and how to hand work over: a brief written for a stranger with an exact check, no keys or personal details, Claude re-running the check and reading the whole diff, and a limit, sign-in, timeout or empty result counted as no answer. On the page, a request moves to Archived 14 days after it was sent once Codex is done and every finding is handled, and a toggle at the top switches between Active, Archived and All. The cog at the top right sets how long Codex must be idle before the band hides itself (10 minutes by default, 0 to keep it up; the band comes back with the next Codex hand-off), the archive age and can turn on deleting archived requests after a number of days (off by default). Deleting removes only the request's entry from the page; Codex's own job records, your code, branches and pull requests are untouched. A light at the left pulses while a job runs. The light and status share a row with three buttons: Details opens your page in the browser, Stop (dim while nothing runs; press twice) cancels that job through the Codex plugin's own cancel, and Hide.

## Pop-up notifications

The band isn't drawn in a session you can't see, such as a Remote Control session a claude.ai project started on your computer. So when one of the session's own Codex jobs starts, finishes, fails or stalls, the mod also raises a system pop-up, in the same step that writes the job's row to your requests page. The pop-up names the job (`Codex review · PR #42 started`), the brief's first line or the finished job's one-line summary, and the Claude task and workspace it came from. It holds no code and stays short, since it can show on a lock screen.

- Windows: a Windows notification raised through PowerShell. Clicking it, or its Open details button, opens your requests page at that job's row (`<page>#<job id>`), which the page opens, scrolls to and highlights.
- macOS: a notification through `osascript`, with the same text. It can't open a link when clicked.
- Linux, WSL and hosted sessions: no pop-up.

The page's cog has a Pop-up notifications section: one switch for all pop-ups, a tick for each of started, finished, failed and stalled (all on by default), and an optional reminder when a job runs longer than a set number of minutes (off by default, 0). The mod reads them when a session starts and every 10 minutes after. A job stopped with Stop gets no pop-up.

Install it from the repository root's README.
